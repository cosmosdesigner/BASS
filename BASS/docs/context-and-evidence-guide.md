# Context And Evidence Guide

**Classification:** Fact for BASS provenance rules. **Confidence:** High.

Start with the project `context-registry.md`; it identifies approved local, Wiki, Work Item, and technical sources. Record material content with source location, confidence, and one classification: `Fact`, `Inference`, `Assumption`, `Proposal`, `Question`, `Conflict`, or `Decision`.

Use the Evidence Register for source lineage, the Decision Log for user resolutions and waivers, and the Action Log for actual confirmed Work Item outcomes. Preserve competing sources as `Conflict`; preserve missing evidence as `Question` or a stated gap. Do not convert either into a fact.

Before a local artifact is persisted, keep its cited preview and explicit approval. Before an ADO Work Item operation, retain the current ADO snapshot, evidence and Decision context, field-level preview, exact plan token, explicit confirmation, actual outcome, and Action Log reference. A local preview or simulated token is not live ADO evidence.

Portable source evidence can support `source_ready`; only retained isolated host evidence can support `target_ready`.
